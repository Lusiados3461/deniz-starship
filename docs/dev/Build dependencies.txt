PROJECT BUILD DEPENDENCIES

Game: Steam Kerbal Space Program 1.12.5 with Making History and Breaking Ground.
Native craft dependencies: SEP, Starship Launch Expansion, B9PartSwitch, Waterfall, Shabby, Resurfaced, CommunityResourcePack, SpaceDust, StationPartsExpansionRedux. kOS and MechJeb support are included in the custom command modules.
The clamshell references the six official Tundra Exploration 5.1.0 cargo assets installed in the personal game folder; the project does not distribute them.
KJR Next 4.2.28 reinforces connections and supports the robotic arm.

Custom plugin build: python3 -B work/starship-pack/build_plugin.py --clean
Requires Python3.9+ and a .NET SDK (runtime alone is insufficient).
Tested compiler: .NET SDK8.0.425, Roslyn C#7.3, existing /nostdlib flags.
No NuGet restore or network needed: references come from the installed KSP1.12.5 app,
Starship Expansion Project and Starship Launch Expansion DLLs. Optional development
builds also require installed MechJeb2, Trajectories and Unity UI assemblies.

SDK lookup: --dotnet-root <root> or DENIZ_KSP_DOTNET_ROOT (explicit values are
strict; invalid values fail), then work/starship-pack/dotnet, tools/dotnet,
PATH dotnet, finally the historical external SDK for compatibility:
~/Documents/Codex/2026-10-02/i-x20-2/work/starship/dotnet
Install/extract the SDK into either local directory to remove that dependency.
The host --list-sdks selects the highest stable installed SDK deterministically;
--sdk-version 8.0.425 pins the tested version.
Missing SDK, requested version, KSP installation or referenced assembly produces
a clear failure before output creation/backup. PROJECT_PATHS.json supplies the
Steam root; --game-root overrides it. Importing either build script is read-only.

Default output: work/starship-pack/DenizStarship.dll. --out <dir>/DenizStarship.dll
keeps assembly identity. Existing output is copied into a dated Backups folder
before compilation. The builder writes only the specified DLL output file; it does
not automatically install craft or restart the game. Default output is project-only;
an explicitly chosen Steam --out path writes there and requires installation backups.
Compile success is static evidence only; changed installed SHA requires native
reload/preservation and relevant flight checks before PROJECT_PATHS acceptance.
Normal play always uses --clean, excluding TestBridge. Optional bridge builds use
build_validation_bridge.py --out <file.dll>, sharing the same SDK/reference checks;
its DLL and outside-GameData flag must be archived before normal play.

Craft/config generator: work/starship-pack/build_pack.py
The geometry reader uses the GPL mu.py copy stored beside the source.
Geometry clearance script needs NumPy; the bundled Codex Python runtime has it installed.

Read PROJECT_LOG.md before running a build. The generator writes to the game installation as well as outputs/Starship Mission Pack. Edited plugin or part definitions require a game restart before they take effect.
Use --clean for the normal playable plugin. The temporary TestBridge is only for controlled development in the separate test save.
